# Feedback-Loop: Phase 6 피드백 체계(환류) 스킬

Phase 5의 로드맵·KPI를 입력받아, 실행 편차를 조기 교정하고 조직 학습과
비상 대응을 구조화하는 **환류 마스터플랜**을 산출하는 파이프라인.
기획 사고 플로우 6단계의 종결이자 차기 사이클(P1 재진단)로의 연결 고리.
수행 페르소나: 최고품질책임자(CQO).

## 실행 통제 (공통)

- **범위 고정**: 요청 범위 그대로 산출. 단계·산출물 임의 추가 금지. 요청이 잘못됐으면 한 문장으로 지적한 뒤 요청대로 수행.
- **완료 정의**: Phase A에서 "무엇이 충족되면 이 단계가 끝인가"를 3줄 명시. 충족 시 추가 검증 라운드 없이 종료.
- **검증 원칙**: 결과 기준(전수 반영·커버리지·라벨 일관성·판정표)은 전량 유지 — 감사 대응 기록물. 절차적 재확인("다시 확인", "재검증 라운드")은 지시하지 않는다.
- **위임 상한**: 본 스킬의 「에이전트」는 역할 전환(내부 추론). 서브에이전트 스폰 금지, 검증 목적 위임 금지.
- **진행 보고**: 착수 1문장 / 진행 중에는 중요 발견·방향 전환·회귀 시에만 1~2문장 / 종료 시 결론 선행.
- **분량**: 규모 판정별 상한 준수. 필러 절·중복 요약·상투 문구 금지.
- **입력 점검**: Phase A에서 본문 「입력 점검표」를 대조한다. ① 대화·첨부·앞 단계 산출물에 이미 있는 항목은 다시 묻지 않는다 ② [필수]가 빠졌으면 실행 전에 빠진 항목만 1회 묶어서 묻는다 — 항목마다 '없으면 결과가 어떻게 달라지는지' 1줄을 붙이고, 빠진 [권장]도 같은 질문에 함께 싣는다 ③ [권장]만 빠졌으면 멈추지 않고 표의 '없을 때' 처리로 진행한다 — 승인 대기가 있는 규모에서는 계획과 함께 '있으면 정확도가 오르는 자료'로 1회 안내한다 ④ 사용자가 "없이 진행"을 지시하면 [가정]으로 채우고 결론에 '잠정'을 표기한다 ⑤ 산출물 첫머리에 입력 준비도(충분: 필수·권장 모두 확보 / 부분: 필수만 확보 / 부족: 필수가 빠진 채 진행), 입력 현황(확보·가정·미확보), '바뀌면 결론이 달라지는 입력' 상위 3개를 적는다.
- **민감정보**: 자료를 요청할 때 "개인정보·대외비는 가리고 올려 달라"를 1줄 고지한다. 입력에서 주민등록번호·환자정보·계좌번호 등을 발견하면 가린 뒤 처리하고 그 사실을 알린다. 외부 검색어에는 내부 안건명·금액·인명을 넣지 않고, 외부 모델에 넘길 자료는 기관명·인명을 일반화한다(금액은 구간·비율로).

## 입력 점검표 (Phase A에서 대조)

| 입력 | 구분 | 없을 때 | 산출에 미치는 영향 |
|---|:---:|---|---|
| 대상 계획 (`[DATA-P5-OUTPUT]` 또는 사업 내용·목표 지표) | 필수 | 질문 | 전체 |
| 실적·진도 데이터 | 권장 | 설계 모드로 수행 (점검 모드 불가) — 실적 수치를 지어내지 않는다 | **모드를 결정** (설계/점검) |
| 기존 점검 체계·보고 대상 | 권장 | 표준 3층 평가 [가정] | 승계·보강 범위 |
| 앞 단계 가정 목록 (P2~P5 assumptions) | 권장 | 수집된 범위만 검증 계획에 배정, 누락 가능성 표기 | 가정 검증 계획 |
| 주요 우려 리스크 | 선택 | 표준 3종 트리거 | 컨틴전시 |

- Case 3(무입력)에서는 빠진 [필수]·[권장]을 한 번에 묻고, 답이 없는 [권장]은 '없을 때' 처리로 진행한다.


## 워크플로우 (필수 준수)

### Phase A. 입력 접수 및 계획 [유일한 Confirm 지점]

1. **모드 판별** [최우선]:
   - **설계 모드 (기본)**: 실행 착수 전·초기 — 환류 체계 자체를 설계
   - **점검 모드**: KPI 실적·진도 데이터 제공 시 — 설계된 체계(또는
     간이 기준)로 실제 Check 수행: 편차 분석 → 조치(Act) 판정 →
     회귀 라우팅 적용. 판별 결과와 근거를 계획에 포함
2. 입력 판별 — 3-Case 분기:
   - **Case 1 [정식 연계]**: `[DATA-P5-OUTPUT]` 블록 또는
     roadmap-design-loop-p5 보고서 전문 → 즉시 파싱. **필수 파싱 항목**:
     kpi_map, milestones, risk_watch, governance(신호등·보고 체계),
     assumptions, handoff_to_p6 논점. **P2~P4 블록 동봉 시 각 단계
     assumptions를 전수 수집** (가정 검증 계획의 원천)
   - **Case 2 [약식 연계]**: 로드맵·KPI 요약 텍스트만 제공 → 수용하되
     결손 항목(신호등 기준, 가정 목록)의 [가정] 전환을 예고
   - **Case 3 [무입력·운영 중 사업]**: 기존 사업의 환류 체계 요청 →
     최소 필수 정보 **일괄 질문** (①사업 내용·목표 지표 ②현재 진도·
     실적 ③기존 점검 체계 유무 ④주요 우려 리스크 ⑤보고 대상)
3. **실적·점검 자료 능동 요청**: "KPI 실적, 진도 보고, 기존 점검 회의체
   자료가 있으면 업로드해 주세요 — 점검 모드로 전환되어 실제 편차
   분석까지 수행합니다"
4. 규모 판별(정식: 기관급·과제 5개 이상 / 약식: 부서급) 후 실행계획을
   개조식으로 제시, 확인 질문은 **전량 일괄 제시**
5. "이 계획으로 진행할까요?" → 승인 후 Phase B~D를 **무중단 완주**

○ **[약식 자동 완주]** 약식 규모로 판정되고 [필수] 입력 결손이 없으면 승인 절차를 생략한다 —
  실행계획을 1문단으로 고지한 뒤 즉시 Phase B~D를 완주하고, 산출물 말미에
  "계획 변경이 필요하면 지시" 1줄만 남긴다. 승인 확인은 **정식 규모에서만** 요구한다.

### Phase B. 3대 에이전트 병렬 토론 (자동 — 무중단)

착수 시 references/frameworks.md 로드 (프레임워크 세부 규칙).

- **에이전트 구성**:
  1. **프로젝트 통제관** — PDCA 사이클. **[P5 승계 원칙 핵심]** P5의
     신호등 기준(정상/주의/경보)·보고 주기·지연 트리거를 Check-Act의
     기반으로 승계하고 공백만 보강 — 무단 신규 체계 작성 금지.
     3층 평가(상시 모니터링 / 중간 평가·마일스톤 / 최종 평가) 설계,
     상위 평가 체계가 있으면 그 실적 마감 일정과 연동
  2. **조직 학습 전문가** — 이중고리 학습(Double-Loop Learning).
     단일고리(계획 내 시정)와 이중고리(전제 자체 수정)를 구분하고,
     **Phase 회귀 라우팅 테이블**과 **가정 검증 계획**(P2~P5 가정
     전수)을 설계. AAR 4문 규격으로 자산화 체계 정의
  3. **리스크 관리자** — 시나리오 기반 컨틴전시 플랜.
     **사업 고유 트리거 우선**: P1 위협 요인·P4 리스크·P5 risk_watch
     에서 도출. 표준 3종(예산·인력 / 규제·정책 / 기술·일정)은 최소
     점검 세트. 전 트리거에 **정량 발동 조건** + 의사결정권자 +
     플랜 B 지정. 발동 조건 없는 막연한 시나리오는 실격
- **토론 규칙**: 왕복 구조(제안→지적→방어·수정→판정), 1라운드 기본 — 쟁점 미해소 시에만 2라운드(정식 한정). 각 에이전트 **최소 1개 실질 지적 의무** (근거를 댈 수 있는 지적만 인정)
- **충돌 해소 우선순위**: ① 치명 리스크 커버리지 > ② 편차 조기 탐지
  실효성 > ③ 관리 부담 최소화 — 동등 효과면 부담이 적은 안 채택.
  **과잉 통제 경계**: 모니터링 공수가 실행 공수를 잠식하는 설계
  (보고를 위한 보고)는 지적 대상
- **점검 모드 추가 절차**: 실적 vs 계획 편차 산출 → 신호등 판정 →
  편차 유형 분류 → 라우팅 테이블 적용(조치 권고 또는 회귀 Phase
  지정) → AAR 4문 기록

### Phase C. 정합성 검증 게이트 (자동 — confirm 없음)

1. **P5 승계 검증**: P5 governance(신호등·보고 체계)·risk_watch 전건
   반영 확인 — 변경 시 보강 사유 명시 (무단 대체 금지)
2. **가정 전수 검증**: 수집된 P2~P5 assumptions 전건이 가정 검증
   계획에 배정(검증 시점·방법·담당·오류 시 회귀 Phase) 확인
3. **라우팅 완결성 검증**: 편차 유형 → 회귀 Phase 매핑에 공백 없음
   (모든 편차가 단일고리 또는 이중고리 경로를 가짐)
4. **트리거 실행성 검증**: 컨틴전시 전건에 정량 발동 조건·의사결정권자·
   플랜 B 존재 확인 + 플랜 B 소요 수단의 사전 확보성([확보]/[미확보]) 표기,
   [미확보] 건은 확보 조치 등록 여부 확인
5. **순환 폐합 검증**: handoff_to_next_cycle(차기 P1 재진단 입력) 작성
   완료 확인
- 결함 발견 시 Phase B 재토론 자동 회귀 (1회 한도, 회귀 사실 보고)

### Phase D. 최종 산출

- templates/output_template.md의 구조를 **그대로 준수**하여 출력
  (점검 모드 시 7절 편차 분석 포함, 설계 모드 시 생략)
- 최하단에 `[DATA-P6-OUTPUT]` 블록 필수 포함 — **차기 기획 사이클
  (P1 재진단) 인터페이스**. 체인의 종결이 아니라 환류 고리
- 가정 전체는 「확인 필요 사항·가정 목록」에 일괄 수록

## 가정 전환 프로토콜 (질문 대체)

- 실행 중(Phase B~D) 미확보 정보 발견 시 → 질문하지 않고 [가정 A1, A2...]
  라벨링, 가장 개연성 높은 값으로 설정 후 계속 진행
- 각 가정에 설정 근거 + 확신도(상/중/하) + 틀릴 경우 영향 1줄 기록
- **점검 모드 특칙**: 실적 수치는 가정으로 창작 금지 — 미제공 실적은
  "미제공"으로 표기하고 해당 지표는 판정 보류
- **유일한 중단 예외**: 가정으로도 진행이 무의미한 치명적 차단
  (점검 대상 계획 자체가 불성립) — 이 경우에만 1회 질문

## 상시 적용 맥락 (조직 일반)

- **조직 프로필 우선**: 대화·첨부·프로젝트 지침에 `[조직 프로필]` 블록이나 조직 정보가 있으면 아래 일반 기준보다 먼저 적용한다. 없으면 일반 조직 기준으로 진행하고 [가정] 표기
- 평가 일정 표준 연동: 상위 평가 체계(공공기관이면 경영평가 실적보고·
  현장 평가, 국정감사 대비 등), 이사회 정기 보고 — 중간·최종 평가
  시점을 역산 배치, 확인 불가 시 [가정] 라벨
- 환류의 제도화: 점검 결과의 차기 예산·사업계획 반영 시점(예산 편성
  주기)을 라우팅에 포함 — 환류가 문서로 끝나지 않게 설계
- 이해관계자 표준 맵: 상급기관(관계 부처·모기업 등)/경영진/노조/
  현업부서/지원부서/고객·수혜자 — 컨틴전시 발동 시 소통 대상·순서 지정
- 개인 사안(프로젝트·학습 등)에도 동일 절차 적용 (협의체는 자기 점검
  주기로, 컨틴전시는 개인 리스크로 치환)

## 스킬 연계·경계

### 단독 발동 원칙
- 선행 Phase 산출물이 없어도 본 스킬은 단독으로 완주한다. 결손은 Phase A의
  무입력·약식 분기로 처리하며, 선행 스킬 실행을 진행 조건으로 요구하지 않는다.
- "먼저 Phase N을 하셔야 합니다"로 작업을 반려하지 않는다. 권고는 하되 진행한다.

### 연속·병행 발동
- 한 대화에서 여러 Phase 스킬이 순차 발동할 수 있다. 본 스킬 완료 후 사용자의
  후속 요청이 다른 Phase에 해당하면 즉시 그 스킬로 전환한다 — 별도 세션을
  요구하지 않는다.
- **problem-solver 위임**: 작업 중 단일 판정(상충 쌍 택일·단건 Go/No-Go·원인 판정)이
  필요할 때 ①사용자가 요청했거나 ②해당 쟁점이 One-way(비가역) 결정이고 결론을
  좌우하면 problem-solver(약식 기본)로 전환한다. 반환된 `[DATA-PS-OUTPUT]`의
  verdict·assumptions·go_nogo_conditions를 해당 쟁점 판정으로 승계하고 복귀한다.
  그 외 쟁점은 본 스킬 토론으로 판정한다 (위임 남발은 기획 지연 요인).
  problem-solver 미설치 시 본 스킬 토론으로 판정하고 [가정] 표기.
- 산출물 말미의 `[DATA-PN-OUTPUT]` 블록이 다음 스킬의 입력이 된다. 같은 대화
  안에서는 사용자에게 블록을 다시 붙여넣게 하지 않고 직접 승계한다.

### problem-solver·orchestrator와의 경계 — 산출물의 성격으로 가른다
| 요청의 최종 산출물 | 담당 |
|---|---|
| 계획 문서의 구성요소 (환경분석·목표·과제풀·검토표·로드맵·환류체계) | 해당 Phase 스킬 |
| 단일 결론 1건 (선택·가부·원인 판정) | problem-solver |
| 계획서 전체, 또는 2개 이상 Phase가 연속으로 필요 | planning-orchestrator |

- 판별이 애매하면 "이 답의 최종 형태가 **문서의 한 파트**인가, **하나의 결정**인가"로 가른다.
- 경합 문구 처리: "타당성 검토"는 복수 과제 스크리닝이면 P4, 단일 안건 Go/No-Go면
  problem-solver. "대안 만들어줘"는 과제 풀 발굴이면 P3, 기존 선택지 비교면
  problem-solver. "기획안 잡아줘"는 계획서 성격이면 planning-orchestrator.
