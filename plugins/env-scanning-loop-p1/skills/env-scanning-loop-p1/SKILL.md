# Env-Scanning-Loop: 오케스트레이터 기반 내외부 환경분석 루프 스킬

보고서·솔루션 착수 전 사전분석 표준 절차.
오케스트레이터 1 + 서브 에이전트 3(PEST / 3C·5F / VRIO) + 종합(SWOT) 구조로,
3대 정합성 가드레일을 통과할 때까지 분석을 반복 고도화하는 루프 파이프라인.

## 실행 통제 (공통)

- **범위 고정**: 요청 범위 그대로 산출. 단계·산출물 임의 추가 금지. 요청이 잘못됐으면 한 문장으로 지적한 뒤 요청대로 수행.
- **완료 정의**: Phase A에서 "무엇이 충족되면 이 단계가 끝인가"를 3줄 명시. 충족 시 추가 검증 라운드 없이 종료.
- **검증 원칙**: 결과 기준(전수 반영·커버리지·라벨 일관성·판정표)은 전량 유지 — 감사 대응 기록물. 절차적 재확인("다시 확인", "재검증 라운드")은 지시하지 않는다.
- **위임 상한**: 본 스킬의 「에이전트」는 역할 전환(내부 추론). 서브에이전트 스폰 금지, 검증 목적 위임 금지.
- **진행 보고**: 착수 1문장 / 진행 중에는 중요 발견·방향 전환·회귀 시에만 1~2문장 / 종료 시 결론 선행.
- **분량**: 규모 판정별 상한 준수. 필러 절·중복 요약·상투 문구 금지.
- **입력 점검**: Phase A에서 본문 「입력 점검표」를 대조한다. ① 대화·첨부·앞 단계 산출물에 이미 있는 항목은 다시 묻지 않는다 ② [필수]가 빠졌으면 실행 전에 빠진 항목만 1회 묶어서 묻는다 — 항목마다 '없으면 결과가 어떻게 달라지는지' 1줄을 붙이고, 빠진 [권장]도 같은 질문에 함께 싣는다 ③ [권장]만 빠졌으면 멈추지 않고 표의 '없을 때' 처리로 진행한다 — 승인 대기가 있는 규모에서는 계획과 함께 '있으면 정확도가 오르는 자료'로 1회 안내한다 ④ 사용자가 "없이 진행"을 지시하면 [가정]으로 채우고 결론에 '잠정'을 표기한다 ⑤ 산출물 첫머리에 입력 준비도(충분: 필수·권장 모두 확보 / 부분: 필수만 확보 / 부족: 필수가 빠진 채 진행), 입력 현황(확보·가정·미확보), '바뀌면 결론이 달라지는 입력' 상위 3개를 적는다.
- **민감정보**: 자료를 요청할 때 "개인정보·대외비는 가리고 올려 달라"를 1줄 고지한다. 입력에서 주민등록번호·환자정보·계좌번호 등을 발견하면 가린 뒤 처리하고 그 사실을 알린다. 외부 검색어에는 내부 안건명·금액·인명을 넣지 않고, 외부 모델에 넘길 자료는 기관명·인명을 일반화한다(금액은 구간·비율로).
- **최신 동향 탐색**: 본문 「최신 동향 탐색」 절과 references/frontier_scan.md에 따라 관련 신규 이론·연구·사례·제도를 1회 탐색해 반영한다. 실제로 연 출처만 싣고, 검색 수단이 없거나 생략했으면 그 사실을 적는다 — 기억으로 최신 동향을 지어내지 않는다.

## 실행 환경별 구동 방식 (필수 확인)
- **기본 환경 = Claude.ai 채팅** (본 스킬의 표준 구동). Claude Code / Cowork의
  Task 병렬 실행 옵션은 본문에서 제외하고 부록으로 이관 — 본문 절차는
  순차 역할 전환을 전제한다
- **Claude.ai 채팅**: 물리적 병렬 불가 → **순차 역할 전환 에뮬레이션**
  (오케스트레이터 → PEST → 3C·5F → VRIO 역할을 순차 수행,
  에이전트 간 인터페이스는 산출물 스키마로 고정)
- **차단 규칙 (순차 에뮬레이션 공통 필수)**: 각 에이전트는 타 에이전트
  산출물 전문을 참조하지 않고 **지정 인터페이스 항목만 수령**
  (PEST 시사점 3개 → 3C, KSF 목록 → VRIO). 각 에이전트 착수 시
  "본 에이전트 입력: (수령 항목)"을 선언 후 분석 개시
- **정밀 모드(이중 실행)는 Claude Code 전용** — Claude.ai에서 정밀
  요청 시 한계 고지 후 정식+차단 규칙으로 대체
- 어느 환경이든 산출물 스키마·게이트 기준·루프 규칙은 동일

## 워크플로우 (필수 준수)

### Phase A. 접수 및 분석 설계 [유일한 Confirm 지점]
1. 안건 분류
   - 유형: 정형(선례·규정 존재) / 복잡(이해관계자 다층) / 긴급
   - 규모: **약식**(소규모·단일 쟁점) / **정식**(복잡·다층 이해관계자) /
     **정밀**(중대 One-way 결정 — Claude Code 전용)
   - 약식 = PEST 축약 + 3C 핵심 (VRIO는 내부 역량 쟁점 존재 시만, 게이트 1회)
   - 정식 = PEST + 3C·5F + VRIO 전체 (게이트 풀가동, Max Loop 2회)
   - 정밀 = **이중 실행 교차검증**: 1차 병렬 독립 실행(Task 서브에이전트)
     + 2차 순차 실행 → 오케스트레이터 **델타 분석**(agents/orchestrator.md
     5장) 후 게이트 검증. Claude.ai 환경에서는 수행 불가 —
     한계 고지 후 정식으로 대체하거나 Claude Code 이관 안내
2. **로컬 자료 일괄 요청**: "이 사안 관련 내부 자료(공문, 실적, 규정,
   기존 분석, 타 기관 자료)가 있으면 업로드해 주세요" — [1급] 근거 확보
3. 분석 설계서 개조식 제시: 적용 기법, 에이전트 편성, 예상 산출물 규모,
   확인 필요 정보 **전량 일괄 질문** (실행 중 추가 질문 금지)
4. "이 설계로 진행할까요?" → 승인 후 Phase B~D **무중단 완주**

○ **[약식 자동 완주]** 약식 규모로 판정되고 [필수] 입력 결손이 없으면 승인 절차를 생략한다 —
  실행계획을 1문단으로 고지한 뒤 즉시 Phase B~D를 완주하고, 산출물 말미에
  "계획 변경이 필요하면 지시" 1줄만 남긴다. 승인 확인은 **정식 규모에서만** 요구한다.

### Phase B. 서브 에이전트 분석 실행
- 각 에이전트 착수 시점에 해당 파일 로드:
  - agents/pest-agent.md — 거시 환경 (정책·경제·사회·기술)
  - agents/market-agent.md — 시장·경쟁 (3C, 정식 시 5F 추가)
  - agents/vrio-agent.md — 내부 역량 (VRIO·가치사슬)
- **웹 검색 의무**: PEST·시장 분석은 최신 데이터 검색 필수,
  검색 불가 항목은 [추정] 명기 — 추정치의 팩트 둔갑 금지
- **영역 침범 금지**: 각 에이전트는 타 에이전트 담당 영역을 분석하지
  않는다 (예: PEST가 내부 역량 평가 금지) — 위반 시 게이트 Fail
- **스키마 준수**: 각 에이전트 출력은 지정 스키마([PEST-OUT] 등) 엄수,
  스키마 이탈 자체가 게이트 Fail 사유
- 가정 전환 프로토콜: 미확보 정보는 질문 없이 [가정 A1, A2...] 라벨링,
  근거 + 확신도(상/중/하) + 틀릴 경우 영향 1줄 기록 후 계속 진행

### Phase C. 정합성 게이트 및 루프 제어 (오케스트레이터)
1. agents/orchestrator.md 로드, 3대 가드레일 검증:
   - **G1 논리 인과**: PEST(기회/위협) → 3C(KSF) → VRIO(대응 역량)
     인과 사슬 연결 여부
   - **G2 데이터 신뢰성**: 근거 위계([1급]~[4급]) 적합성, 추정 표기 여부
   - **G3 MECE**: 중대 이해관계자·분석 축 누락 여부
2. **게이트 판정표 필수 출력** (templates/gate_check.md):
   게이트별 Pass/Fail + 판정 사유 + 반려 지시 명기 — 판정표 없는 통과 금지
3. **반례 탐색 의무**: 오케스트레이터는 판정 전 각 분석의 반례·모순
   가능성을 1개 이상 명시적으로 탐색한 후 판정 (자기 옹호 금지)
4. Fail 시 **국소 반려**: 결함 에이전트만 재수행 지시 (전체 롤백 금지)
5. **Max Loop = 2회 (이스케이프 룰)**: 2회 초과 시 루프 강제 종료,
   최고 정합성 안 강제 채택 + 미해결 항목을 최종 보고서
   "잔여 리스크" 절에 전량 명기

### Phase D. 종합 및 산출
1. SWOT 도출: SO/ST/WO/WT 교차 전략, 각 전략을 G1 인과 사슬에 매핑
2. templates/env_report.md 기준 최종 보고서 작성
3. 비판적 검토 — **Critical Review 1회로 일원화**:
   - 첫 줄은 "이 분석을 근거로 다음 단계에 착수하면 안 되는 가장 강한 이유 1개"
   - 이어 한계·위험 → 추가 검증 필요 → 잔여 리스크
   - 자체 반대심문 3문 등 별도 검증 절차는 중복이므로 두지 않는다
4. 세션 인계 요약 출력: 현재 단계 / 확정 사항 / 미결 사항 /
   다음 착수점 10줄 내외

## 스킬 연계·경계

### 단독 발동 원칙
- 선행 Phase 산출물이 없어도 본 스킬은 단독으로 완주한다. 결손은 Phase A의
  무입력·약식 분기로 처리하며, 선행 스킬 실행을 진행 조건으로 요구하지 않는다.
- "먼저 Phase N을 하셔야 합니다"로 작업을 반려하지 않는다. 권고는 하되 진행한다.

### 연속·병행 발동
- 한 대화에서 여러 Phase 스킬이 순차 발동할 수 있다. 본 스킬 완료 후 사용자의
  후속 요청이 다른 Phase에 해당하면 즉시 그 스킬로 전환한다 — 별도 세션을
  요구하지 않는다.
- **problem-solver 위임**: 작업 중 단일 판정(상충 쌍 택일·단건 Go/No-Go·원인 판정)이
  필요할 때 ①사용자가 요청했거나 ②해당 쟁점이 One-way(비가역) 결정이고 결론을
  좌우하면 problem-solver(약식 기본)로 전환한다. 반환된 `[DATA-PS-OUTPUT]`의
  verdict·assumptions·go_nogo_conditions를 해당 쟁점 판정으로 승계하고 복귀한다.
  그 외 쟁점은 본 스킬 토론으로 판정한다 (위임 남발은 기획 지연 요인).
  problem-solver 미설치 시 본 스킬 토론으로 판정하고 [가정] 표기.
- **본 스킬(P1)은 정형 `[DATA-P1-OUTPUT]` 블록을 출력하지 않는다.** 환경분석은
  서술 맥락이 산출물의 본질이므로, `templates/env_report.md` 보고서 자체가
  인계 단위다. 후행 P2는 이 보고서의 SWOT·교차 전략·제약·가정을 Case 1
  입력으로 파싱한다 (orchestrator Q-Gate도 P1만 유연 검증으로 처리).
- 같은 대화 안에서는 사용자에게 산출물을 다시 붙여넣게 하지 않고 직접 승계한다.

### problem-solver·orchestrator와의 경계 — 산출물의 성격으로 가른다
| 요청의 최종 산출물 | 담당 |
|---|---|
| 계획 문서의 구성요소 (환경분석·목표·과제풀·검토표·로드맵·환류체계) | 해당 Phase 스킬 |
| 단일 결론 1건 (선택·가부·원인 판정) | problem-solver |
| 계획서 전체, 또는 2개 이상 Phase가 연속으로 필요 | planning-orchestrator |

- 판별이 애매하면 "이 답의 최종 형태가 **문서의 한 파트**인가, **하나의 결정**인가"로 가른다.
- 경합 문구 처리: "타당성 검토"는 복수 과제 스크리닝이면 P4, 단일 안건 Go/No-Go면
  problem-solver. "대안 만들어줘"는 과제 풀 발굴이면 P3, 기존 선택지 비교면
  problem-solver. "기획안 잡아줘"는 계획서 성격이면 planning-orchestrator.
