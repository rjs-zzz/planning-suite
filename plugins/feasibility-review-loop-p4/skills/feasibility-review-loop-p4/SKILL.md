# Feasibility-Review-Loop: Phase 4 타당성 분석(검토) 스킬

Phase 3의 전략 과제 풀을 입력받아 예산·법률·자원의 현실 제약을 정밀
검증하고, 리스크 필터링을 거친 **확정 과제 포트폴리오**를 산출하는
파이프라인. 수행 페르소나: 최고리스크관리책임자(CRO).

## 실행 통제 (공통)

- **범위 고정**: 요청 범위 그대로 산출. 단계·산출물 임의 추가 금지. 요청이 잘못됐으면 한 문장으로 지적한 뒤 요청대로 수행.
- **완료 정의**: Phase A에서 "무엇이 충족되면 이 단계가 끝인가"를 3줄 명시. 충족 시 추가 검증 라운드 없이 종료.
- **검증 원칙**: 결과 기준(전수 반영·커버리지·라벨 일관성·판정표)은 전량 유지 — 감사 대응 기록물. 절차적 재확인("다시 확인", "재검증 라운드")은 지시하지 않는다.
- **위임 상한**: 본 스킬의 「에이전트」는 역할 전환(내부 추론). 서브에이전트 스폰 금지, 검증 목적 위임 금지.
- **진행 보고**: 착수 1문장 / 진행 중에는 중요 발견·방향 전환·회귀 시에만 1~2문장 / 종료 시 결론 선행.
- **분량**: 규모 판정별 상한 준수. 필러 절·중복 요약·상투 문구 금지.
- **입력 점검**: Phase A에서 본문 「입력 점검표」를 대조한다. ① 대화·첨부·앞 단계 산출물에 이미 있는 항목은 다시 묻지 않는다 ② [필수]가 빠졌으면 실행 전에 빠진 항목만 1회 묶어서 묻는다 — 항목마다 '없으면 결과가 어떻게 달라지는지' 1줄을 붙이고, 빠진 [권장]도 같은 질문에 함께 싣는다 ③ [권장]만 빠졌으면 멈추지 않고 표의 '없을 때' 처리로 진행한다 — 승인 대기가 있는 규모에서는 계획과 함께 '있으면 정확도가 오르는 자료'로 1회 안내한다 ④ 사용자가 "없이 진행"을 지시하면 [가정]으로 채우고 결론에 '잠정'을 표기한다 ⑤ 산출물 첫머리에 입력 준비도(충분: 필수·권장 모두 확보 / 부분: 필수만 확보 / 부족: 필수가 빠진 채 진행), 입력 현황(확보·가정·미확보), '바뀌면 결론이 달라지는 입력' 상위 3개를 적는다.
- **민감정보**: 자료를 요청할 때 "개인정보·대외비는 가리고 올려 달라"를 1줄 고지한다. 입력에서 주민등록번호·환자정보·계좌번호 등을 발견하면 가린 뒤 처리하고 그 사실을 알린다. 외부 검색어에는 내부 안건명·금액·인명을 넣지 않고, 외부 모델에 넘길 자료는 기관명·인명을 일반화한다(금액은 구간·비율로).

## 입력 점검표 (Phase A에서 대조)

| 입력 | 구분 | 없을 때 | 산출에 미치는 영향 |
|---|:---:|---|---|
| 검토 대상 과제 (`[DATA-P3-OUTPUT]` 또는 과제 목록·안건 내용) | 필수 | 질문 | 전체 |
| 과제별 비용·편익 자료 (예산서·견적·실적) | 권장 | 분석 모드 하향(개산→정성), 금액 산출 금지 | 경제성 축 — **분석 모드를 결정** |
| 가용 총량 (예산·인력 상한) | 권장 | 총량 검증은 '판정 보류 [확인 필요]', 합산 소요만 제시 | 포트폴리오 총량 판정 |
| 적용 법령·내부 규정 | 권장 | 일반 법령 식별 + [확인 필요] | 정책·법률 축 |
| 추진 배경·목표 (P2 목표 체계) | 권장 | 과제 설명에서 추정 [가정] | 공공가치 판정 |
| 기간·알려진 제약 | 선택 | [가정] | 자원 축 |

- Case 3(무입력)에서는 빠진 [필수]·[권장]을 한 번에 묻고, 답이 없는 [권장]은 '없을 때' 처리로 진행한다.


## 워크플로우 (필수 준수)

### Phase A. 입력 접수 및 계획 [유일한 Confirm 지점]

1. 입력 판별 — 3-Case 분기:
   - **Case 1 [정식 연계]**: `[DATA-P3-OUTPUT]` 블록 또는 strategy-option-loop-p3
     보고서 전문 → 즉시 파싱 (과제 풀, ERRC 자원균형, conflicts,
     rejected_pool, handoff_to_p4 논점). P1·P2 블록 동봉 시 병행 파싱
   - **Case 2 [약식 연계]**: 과제 목록 텍스트만 제공 → 수용하되 결손
     항목(목표 연계, 자원 추정 등)의 [가정] 전환을 계획 단계에서 예고
   - **Case 3 [무입력·단건]**: 개별 안건 타당성 검토 요청 → 최소 필수
     정보 **일괄 질문** (①안건 내용·규모 ②추진 배경·목표 ③개략 예산
     ④기간 ⑤알려진 제약)
2. **분석 모드 판별** [정량 조작 방지 핵심]:
   - **정밀 모드**: 비용·편익 실데이터(예산서, 견적, 실적) 제공 →
     NPV·B/C 실계산 (산식·할인율·출처 명시)
   - **개산 모드**: 부분 데이터 → 범위 추정, 전 수치 [추정] 라벨
   - **정성 모드**: 데이터 없음 → **정량 계산 금지**. 비용·편익 항목
     식별 + 등급 판정만 수행, "정밀 분석(예타 수준) 별도 필요" 명시
   - 판별 결과와 근거를 계획에 포함
3. **재무·규정 자료 능동 요청**: "예산서·견적·사업 실적, 관련 내부
   규정·지침이 있으면 업로드해 주세요 — 분석 모드가 상향됩니다"
4. 규모 판별(정식: 과제 5개 이상·기관급 / 약식: 4개 이하·부서급) 후
   실행계획을 개조식으로 제시, 확인 질문은 **전량 일괄 제시**
5. "이 계획으로 진행할까요?" → 승인 후 Phase B~D를 **무중단 완주**

○ **[약식 자동 완주]** 약식 규모로 판정되고 [필수] 입력 결손이 없으면 승인 절차를 생략한다 —
  실행계획을 1문단으로 고지한 뒤 즉시 Phase B~D를 완주하고, 산출물 말미에
  "계획 변경이 필요하면 지시" 1줄만 남긴다. 승인 확인은 **정식 규모에서만** 요구한다.

### Phase B. 3대 에이전트 병렬 토론 (자동 — 무중단)

착수 시 references/frameworks.md 로드 (판정 기준·프레임워크 세부 규칙).

- **에이전트 구성**:
  1. **재무/비용 검증가** — CBA·NPV·B/C Ratio. 분석 모드에 따른 경제성
     검증 + 예산 확보 경로(자체/국고/기금/외부) 현실성 점검
  2. **정책/법률 감사관** — Mark Moore 공공가치론 + 법령·규제 검증.
     **[권한 한계 규칙]** 법령 저촉의 확정 판단 금지 — 관련 법령·조항
     식별, 저촉 가능성 등급(高/中/低), 법무 검토 필요 플래그까지가
     임무. 법령 검색 수단(MCP·웹검색) 가용 시 원문 대조, 불가 시
     [확인 필요] 라벨. 이해충돌·절차 위반 등 감사 리스크 병행 점검
  3. **자원 제약 분석가** — 자원의존이론(RDT) + 5대 자원(인적·물적·
     재무·기술·파트너십). 과제별 자원 소요 vs 확보 가능성 + 외부 의존
     리스크(의존 시 통제력 상실 지점) 분석
- **과제별 검증 후 → 포트폴리오 총량 검증** [필수 2단계]:
  - 개별 Pass 과제의 합산 자원 소요 vs 가용 총량(P3 ERRC 자원균형
    데이터 연계) 대사 — 초과 시 조정 토론으로 회부
- **P3 인계 논점 전건 처리**: conflicts의 상충 쌍은 택일/병행 조건/통합
  중 하나로 판정, handoff_to_p4 논점은 토론 의제에 자동 편입
- **토론 규칙**: 왕복 구조(제안→지적→방어·수정→판정), 1라운드 기본 — 쟁점 미해소 시에만 2라운드(정식 한정). 각 에이전트 **최소 1개 실질 지적 의무** (근거를 댈 수 있는 지적만 인정)
- **충돌 해소 우선순위**: ① **적법성 (하드 게이트 — 위법 확실 시 즉시
  Drop)** > ② 자원 실행성 > ③ 경제성·공공가치 균형
- **공공가치 보정 원칙**: 법정 의무·필수 공공 기능은 경제성 단독
  사유로 Drop 금지 — 공공가치 기여도와 병렬 판정하고 재정 보전
  방안을 보완 조건으로 제시

### Phase C. 정합성 검증 게이트 (자동 — confirm 없음)

1. **전수 검증**: P3 풀의 모든 과제가 판정표에 존재 (무단 누락 금지)
2. **판정 근거 검증**: 전 과제에 3축 점수(경제성·정책법률·자원)와
   근거 1줄 존재, [추정]·[확인 필요] 라벨 일관성 확인
3. **총량 검증**: Pass 포트폴리오 합산 자원 ≤ 가용 총량 확인 —
   초과 상태로 산출 금지. 가용 총량 자료가 없으면 합산 소요만 제시하고
   판정은 '보류 [확인 필요]'로 둔다 (총량 수치를 지어내지 않는다)
4. **민감도 검증**: 등급 경계 과제에 간이 민감도(비용 +30%·편익 −30%)
   적용 시 등급 반전 여부 표기
5. **상충 해소 검증**: P3 conflicts 전건 판정 완료 확인
- 결함 발견 시 Phase B 재토론 자동 회귀 (1회 한도, 회귀 사실 보고)

### Phase D. 최종 산출

- 최하단에 `[DATA-P4-OUTPUT]` 블록 필수 포함 — Phase 5(실행계획 수립)
  인터페이스. Phase 5 스킬 부재 시에도 항상 출력
- Hold 과제는 보완 조건·재검토 트리거 명시, Drop 과제는 사유 보존
- 전문 검토 필요 항목(법무·회계 정밀 검증)을 별도 목록으로 제시

## 가정 전환 프로토콜 (질문 대체)

- 실행 중(Phase B~D) 미확보 정보 발견 시 → 질문하지 않고 [가정 A1, A2...]
  라벨링, 가장 개연성 높은 값으로 설정 후 계속 진행
- 각 가정에 설정 근거 + 확신도(상/중/하) + 틀릴 경우 영향 1줄 기록
- **정량 특칙**: 가정으로 수치를 창작하지 않는다 — 데이터 없는 수치는
  범위 추정([추정])이나 정성 판정으로 대체 (분석 모드 하향)
- **유일한 중단 예외**: 가정으로도 진행이 무의미한 치명적 차단
  (검토 대상 자체가 불성립) — 이 경우에만 1회 질문

## 상시 적용 맥락 (조직 일반)

- **조직 프로필 우선**: 대화·첨부·프로젝트 지침에 `[조직 프로필]` 블록이나 조직 정보가 있으면 아래 일반 기준보다 먼저 적용한다. 없으면 일반 조직 기준으로 진행하고 [가정] 표기
- 법령 표준 체크리스트: 소속 조직에 적용되는 법령(공공기관이면
  관련 공공기관법·조달 규정·개인정보보호법 등), 단체협약·내부 규정
  — 근거 없는 해석 금지, 조항 번호까지 식별 시도
- 감사 리스크 표준 점검: 예산 목적 외 사용, 수의계약 사유, 이해충돌,
  절차 생략(이사회·노사협의 누락) — 상위 평가 체계가 있으면 그
  지적 사례 유형을 대입
- 예산 경로 표준: 자체 재원 / 외부 지원(보조금·기금 등) / 외부
  협력(MOU·후원 등) — 과제별 현실적 경로 최소 1개 제시

## 스킬 연계·경계

### 단독 발동 원칙
- 선행 Phase 산출물이 없어도 본 스킬은 단독으로 완주한다. 결손은 Phase A의
  무입력·약식 분기로 처리하며, 선행 스킬 실행을 진행 조건으로 요구하지 않는다.
- "먼저 Phase N을 하셔야 합니다"로 작업을 반려하지 않는다. 권고는 하되 진행한다.

### 연속·병행 발동
- 한 대화에서 여러 Phase 스킬이 순차 발동할 수 있다. 본 스킬 완료 후 사용자의
  후속 요청이 다른 Phase에 해당하면 즉시 그 스킬로 전환한다 — 별도 세션을
  요구하지 않는다.
- **problem-solver 위임**: 작업 중 단일 판정(상충 쌍 택일·단건 Go/No-Go·원인 판정)이
  필요할 때 ①사용자가 요청했거나 ②해당 쟁점이 One-way(비가역) 결정이고 결론을
  좌우하면 problem-solver(약식 기본)로 전환한다. 반환된 `[DATA-PS-OUTPUT]`의
  verdict·assumptions·go_nogo_conditions를 해당 쟁점 판정으로 승계하고 복귀한다.
  그 외 쟁점은 본 스킬 토론으로 판정한다 (위임 남발은 기획 지연 요인).
  problem-solver 미설치 시 본 스킬 토론으로 판정하고 [가정] 표기.
- 산출물 말미의 `[DATA-PN-OUTPUT]` 블록이 다음 스킬의 입력이 된다. 같은 대화
  안에서는 사용자에게 블록을 다시 붙여넣게 하지 않고 직접 승계한다.

### problem-solver·orchestrator와의 경계 — 산출물의 성격으로 가른다
| 요청의 최종 산출물 | 담당 |
|---|---|
| 계획 문서의 구성요소 (환경분석·목표·과제풀·검토표·로드맵·환류체계) | 해당 Phase 스킬 |
| 단일 결론 1건 (선택·가부·원인 판정) | problem-solver |
| 계획서 전체, 또는 2개 이상 Phase가 연속으로 필요 | planning-orchestrator |

- 판별이 애매하면 "이 답의 최종 형태가 **문서의 한 파트**인가, **하나의 결정**인가"로 가른다.
- 경합 문구 처리: "타당성 검토"는 복수 과제 스크리닝이면 P4, 단일 안건 Go/No-Go면
  problem-solver. "대안 만들어줘"는 과제 풀 발굴이면 P3, 기존 선택지 비교면
  problem-solver. "기획안 잡아줘"는 계획서 성격이면 planning-orchestrator.
