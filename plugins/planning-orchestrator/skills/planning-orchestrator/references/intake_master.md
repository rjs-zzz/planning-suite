# 통합 입력 점검 (통합 모드 — 전 단계분 자료를 1회에 요청)

운영 계획 단계(Phase A)에서 로드한다. 각 Phase 스킬 본문의 「입력 점검표」를
자료 종류별로 묶은 것이다. 내용이 다르면 각 스킬 본문이 우선한다.
이미 받은 자료는 다시 묻지 않는다.

## 1. 공통 필수 (없으면 질문)

- 기획 주제와 최종 산출물 — 무슨 계획서인가
- 대상 조직 — 유형·상급기관 (`[조직 프로필]` 블록이면 충분)
- 계획 기간과 시작 시점

## 2. 자료 묶음표 (권장 — 없으면 '없을 때' 처리로 진행)

| 묶음 | 자료 | 쓰는 Phase | 없을 때 |
|:---:|---|---|---|
| A 방침 | 기존 미션·비전, 상위 계획, 평가 지표 체계 | P1·P2 | 신규 수립 [가정], 상위 정합 점검은 약식 |
| B 실적 | 최근 실적·현황 수치, 기존 분석 | P1·P2·P6 | 내부 분석 [추정] / KR 기준선 [확인 필요] / P6는 설계 모드 |
| C 현행 사업 | 사업·업무 목록 | P3 | 제거·축소 항목 [가정] |
| D 재무 | 예산서·견적, 가용 예산·인력 상한 | P3·P4·P5 | P4는 금액 없이 등급 판정, 총량 판정 보류 |
| E 조직·일정 | 조직도·업무분장, 고정 일정(이사회·예산 편성·평가) | P5 | 기능 역할 명칭, 표준 캘린더 [가정] |
| F 규정 | 적용 법령·내부 규정·단체협약 | P4 | 일반 법령 식별 + [확인 필요] |
| G 점검 체계 | 기존 점검 회의체, 보고 대상 | P6 | 표준 3층 평가 [가정] |

- 진입 Phase 이후에 쓰이는 묶음만 요청한다 (P3에서 시작하면 A는 묻지 않는다).
- 요청 문구는 묶음 단위로 짧게, 없을 때의 결과를 붙인다.
  예: "D 재무 자료(예산서·견적, 가용 상한)가 있으면 올려 주세요 — 없으면 P4는 금액 없이 등급 판정만 합니다."
- 자료 요청에는 "개인정보·대외비는 가리고 올려 달라"를 1줄 붙인다.

## 3. 입력 현황 기록

- 운영 계획에 묶음별 확보 여부를 1줄로 적는다 (예: "확보 A·B·C / 미확보 D·E·F·G").
- [ORCH-STATE]의 `inputs_missing`에 미확보 묶음을 남긴다 — 세션이 바뀌어도 이어진다.
- 각 Phase 착수 시 그 Phase가 쓰는 묶음의 확보 여부를 1줄 선언하고, 다시 묻지 않고 진행한다.
- 사용자가 뒤늦게 자료를 주면 그 묶음을 쓰는 Phase만 재실행 대상으로 안내한다 (전체 재실행 금지).

## 4. 사용자용 양식 (준비물·입력 양식을 물으면 그대로 출력)

```
[계획 수립 요청]
1. (필수) 기획 주제 — 무슨 계획서인가:
2. (필수) 대상 조직:
3. (필수) 계획 기간·시작 시점:
4. 이미 있는 것 — 환경분석 / 목표 체계 / 과제 목록 등:
5. 첨부 자료 (있는 것만)
   A 방침(미션·비전·상위 계획) / B 실적 수치 / C 현행 사업 목록 /
   D 재무(예산서·견적·가용 상한) / E 조직도·고정 일정 / F 법령·규정 / G 점검 체계
6. 진행 방식 — 한 세션에서 이어서 / 단계별로 나눠서, 단계마다 확인 / 자동 진행:

[조직 프로필]   ← 한 번 써 두고 재사용
- 조직 유형: (예: 공공기관 / 지자체 / 민간기업 / 병원 / 학교)
- 상급·감독 기관:
- 자주 걸리는 법령·규정:
- 평가·감사 체계: (예: 경영평가, 감사, 이사회 보고)
- 승인 경로: (예: 부서장 전결 → 경영진 → 이사회)
- 주요 이해관계자:
- 예산 주기·고정 일정:

※ 개인정보·대외비는 가리고 올려 주세요.
```
