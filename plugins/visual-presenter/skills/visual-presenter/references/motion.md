# 모션 규칙 (Motion)

모션을 쓸 때 로드한다. 어떤 움직임을 쓸지는 Phase B에서 찾은 실제 사례가 정한다. 이 파일은 지킬 것을 정하고, motion_catalog.md는 기법 이름과 구현 등급을 확인하는 데 쓴다.

## 1. 두 가지 모드

| 모드 | 언제 | 성격 | 길이 |
|---|---|---|---|
| 설명 모드 (기본) | 도식·차트를 이해시키는 것이 목적 | 절제. 무엇이 바뀌었는지 알리는 용도 | 그림당 3초 안팎 |
| 연출 모드 | 오프닝, 하이라이트, 대외 홍보, 사용자가 "화려하게"를 요청 | 표현적. 인상과 리듬을 만든다 | 화면 5~20초, 영상 1분 안팎 |

- 사용자가 모드를 말하지 않았으면 용도로 정한다: 보고·점검은 설명, 발표 오프닝·대외 공유는 연출. 정한 모드를 첫 줄에 밝힌다. [설계]

## 2. 기법 고르기

1. Phase B에서 고른 실제 사례의 움직임에서 출발한다. 그 움직임이 무엇을 설명했는지 먼저 적는다.
2. 이 내용에서 같은 뜻을 내는 움직임을 정하고, motion_catalog.md에서 이름과 구현 등급을 확인한다. 카탈로그에 없으면 새 이름으로 쓰고 `○ 스킬 개선 후보`로 남긴다.
3. 사용자가 기법을 지정하면 그것을 쓴다. 등급이 '기획'이면 만들 수 없음을 밝히고 구성안만 낸다.
4. 한 번에 하나만 움직인다. 처음 화면의 연출은 한 번이면 충분하다. 구획마다 같은 등장 효과를 반복하지 않는다. [직접]
5. 뜻 없는 움직임은 넣지 않는다. 움직임마다 "이 움직임은 ○○를 보여 준다"를 한 문장으로 쓸 수 있어야 한다. [설계 — 사용자 요청]

## 3. 지킬 것 (두 모드 공통)

- 마지막 화면은 그 자체로 완결돼야 한다. 움직임을 보지 못한 사람도 내용을 다 읽을 수 있어야 한다. [설계]
- 움직임을 끈 기기에서는 즉시 마지막 화면을 보여 준다. [직접]
- 깜빡임은 초당 3회를 넘기지 않는다. 화면 전체가 번쩍이거나 명암이 뒤집히는 장면을 넣지 않는다. [직접]
- 글자는 읽을 시간을 준다. 문장은 멈춘 상태로 1초 이상 보여 준다. [설계]
- 수치·순위가 바뀌는 움직임에서는 같은 항목이 같은 도형으로 이어져야 한다 (항목을 추적할 수 있게). [직접]
- 형식이 바뀌는 전환은 단계를 나눈다 (점이 줄을 맞춘 뒤 막대로 바뀐다). [직접]
- 움직임이 데이터의 뜻을 바꾸지 않게 한다. 탄성·과장으로 막대가 실제 값보다 커 보이는 순간이 길면 안 된다. [설계]

## 4. 모드별 규칙

### 설명 모드
- 한 번에 하나만 움직인다. [직접]
- 요소 하나의 움직임은 0.15~0.4초, 큰 요소일수록 길게. [직접]
- 반복 재생은 '흐름'류 기법에만 쓴다. 나머지는 한 번 재생하고 멈추며 다시 보기 단추를 둔다. [설계]
- 질감·왜곡·카메라 흔들림 계열(카탈로그 ⑤, ③의 일부)은 쓰지 않는다. [설계]

### 연출 모드
- 장면마다 주된 기법 1개, 보조 기법 1개까지 쓴다. [설계]
- 장면은 5개 이내. 장면마다 "한 문장 + 그림 하나"를 둔다. [설계]
- 왜곡·글리치·흔들림은 한 산출물에 1~2번, 뜻이 있는 지점(문제 제기, 전환점)에만 쓴다. [설계]
- 연출 장면 뒤에는 정보를 읽을 수 있는 정지 구간을 둔다. [설계]

## 5. 영상이 필요할 때

- 화면 안의 움직임이 아니라 영상 파일이 필요하면 별도 산출물로 만든다. 보고서 본문에 넣지 않는다.
- 영상은 한 장 요약(10A)의 내용을 다룬다. 구성안(장면·문장·그림·기법·길이)을 먼저 내고, 확인을 받은 뒤 만든다.
- 구현 등급이 '기획'인 기법(촬영·3D 제작·물리 연산)은 구성안까지만 낸다. 영상 제작 도구나 전문 제작이 필요하다고 밝힌다.
