# 실제 사례 벤치마킹 (Benchmark)

그림을 그릴 때마다 먼저 실제 사이트에서 이 내용에 맞는 사례를 찾는다. 미리 정해 둔 스타일은 쓰지 않는다.
기억 속 기본값으로 그리면 'AI가 만든 티'가 난다. 실제로 잘 만든 작품에서 구성 원칙을 가져와야 그 티가 빠진다.

## 1. 어디서 찾나 (출발점 — 고정 목록이 아니다)

| 종류 | 출발점 | 볼 것 |
|---|---|---|
| 데이터 스토리·스크롤리텔링 | The Pudding, NYT·WSJ·Reuters 그래픽 기사, FlowingData | 중심 은유, 장면 순서, 글과 그림의 비율 |
| 웹 모션 기법·구현 해설 | Codrops, GSAP 쇼케이스, Awwwards(storytelling·scrolling 모음) | 움직임의 구조, 타이밍, 스크롤과의 연결 |
| 모션그래픽·설명 영상 | Motionographer, Behance(Motion), Vimeo Staff Picks, Pinterest | 장면 전환, 손맛, 색·글자 절제 |
| 인포그래픽·편집 디자인 | Information is Beautiful Awards, Behance(Infographic) | 한 장 구성, 주석 다는 법 |

- 이 표는 출발점이다. 내용에 더 맞는 곳이 있으면 거기서 찾는다.
- 사진·3D가 중심인 상업 사이트는 분석 산출물과 거리가 멀다. 고를 때 이 점을 감안한다.

## 2. 절차

1. **내용의 성격을 한 문장으로 쓴다.** 구조 / 흐름·일정 / 비교 / 추세 / 강조할 한 문장 중 무엇인가.
2. **검색한다 (2~4회).** 검색어는 "내용 유형 + 형식 + 기법어"로 쓰고 영문을 함께 쓴다.
   예: "timeline scrollytelling line drawing", "two paths diverge infographic", "data story zoom transition".
   내부 안건명·기관명·금액·인명은 넣지 않는다.
3. **실제 작품 2~3개를 연다.** 브라우저로 화면을 볼 수 있으면 스크롤하며 본다. 볼 수 없으면 글 설명으로 판단했다고 밝힌다. 열리지 않으면 "열리지 않음"이라고 적는다.
4. **작품마다 세 가지만 뽑는다.**
   - 중심 은유: 내용을 무엇으로 바꿔 보여 주는가 (예: 일정 → 갈라졌다 다시 만나는 길)
   - 움직임의 뜻: 움직임이 무엇을 설명하는가 (예: 원이 굴러 π를 보여 줌). 뜻 없는 움직임은 가져오지 않는다.
   - 절제: 색 수, 글꼴 수, 빼 버린 장식
5. **방향 2~3개로 정리해 Phase C에서 묻는다.**
   `방향 이름 | 참고 작품(링크) | 가져올 것 | 구현 등급(직접·근사·기획)`
6. **그대로 옮기지 않는다.** 구성 원칙만 가져온다. 특정 작품·브랜드의 화면, 캐릭터, 글꼴 조합을 재현하지 않는다.
7. **실제로 연 것만 싣는다.** 검색 결과 제목만 보고 내용을 지어내지 않는다.

## 3. 중심 그림 먼저

- 사례를 고른 뒤, 이번 산출물의 중심 은유를 한 문장으로 정한다. 모든 장면은 이 은유 위에서 움직인다.
- 이야기의 모양을 정한다. 넓게 → 한 점으로 좁게 → 다시 넓게가 기본이다. 평평하게 나열하지 않는다.
- 같은 뼈대에 색만 바꾼 시안을 여러 개 내지 않는다. 시안을 여러 개 낼 때는 중심 은유가 달라야 한다.

## 4. AI 티 점검표 (만든 뒤 대조 — 하나라도 해당하면 고친다)

- 같은 모양의 둥근 카드가 반복되고 같은 그림자가 깔려 있다
- 작은 고정폭 라벨, 대문자 라벨, '·'로 이어 붙인 메타 문구가 있다
- 크림색 바탕 + 세리프 + 주황 강조, 또는 검정 바탕 + 형광 강조다
- 네온 발광, 글로우, 그라디언트 면을 장식으로 썼다
- 큰 숫자 + 작은 라벨 + 강조색 묶음을 습관처럼 썼다
- 내용과 맞지 않는 은유를 썼다 (일정을 게이지로, 절차를 계기판으로)
- 모든 요소가 한꺼번에 움직이거나, 구획마다 같은 페이드업이 반복된다
- 제목의 한 단어만 색이나 굵기로 강조했다
- 내용과 무관한 장식 아이콘이 있다

## 5. 글꼴·색

- 색은 역할로 정한다: 바탕 / 글자 / 주색 / 보조색. 조직 색을 받았으면 주색·보조색 자리에 넣는다.
- 강조색은 1~2개. 상태(양호·주의·위험)에는 색과 함께 글자를 쓴다.
- 외부 글꼴은 Google Fonts만 쓰고, 반드시 기기 글꼴을 대체로 지정한다. 대체 글꼴로 보여도 읽히는지 확인한다.

## 6. 기록

- 산출물 끝에 「참고한 실제 사례」로 작품 이름과 링크를 남긴다.
- 좋은 결과를 낸 사례와 기법은 `○ 스킬 개선 후보`로 1줄 남긴다. 월간 점검에서 이 파일의 출발점 표에 넣을지 정한다.
