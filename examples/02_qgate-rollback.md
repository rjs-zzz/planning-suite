# 예시 2 — Q-Gate Rollback 판정 (`planning-orchestrator`)

> 이 세트의 핵심 기능은 "단계 간 정합 검증과 **재전파 범위 한정**"이다.
> 아래는 P5 산출물 접수 후 모순이 발견되어 P2로 되돌린 실제 출력 형태다.
> 조직·수치는 가상이다.

---

## 입력

사용자가 `[DATA-P5-OUTPUT]` 블록을 붙여넣음. (앞선 P2·P4 블록도 상태 원장에 보유)

---

## 산출물

## 【 기획 관제 대시보드 — 한국○○진흥원 3개년 계획 (cycle 1) 】

### 1. State Track

```
P1 진단 ▣ → P2 목표 ▣ → P3 전략 ▣ → P4 검토 ▣ → P5 실행 ▨ → P6 환류 ▢
```

### 2. Q-Gate 검증 보고 (P5 → P6)

| 검증 항목 | 결과 | 상세 |
|---|:---:|---|
| 스키마 필수 필드 | Pass | 10개 필드 전건 존재 |
| 이월 플래그 | **Fail** | P4 `conditional_pool` 3건 중 1건(T7 이행 조건)이 `prerequisites_tracks`에 미반영 |
| 상호 참조 | **Fail** | `kpi_map` KR 참조 7건 중 3건이 P2 `okr_summary`에 부재 — [신규] 라벨 KPI가 과반 |
| 회귀 신호 | 탐지 | 임계 경로는 식별됨. 단 [신규] KPI 과반은 **P2 목표 체계 결함 신호** |

### 3. 판정 — **Rollback (목적지: P2)**

○ 판정 근거: [신규] KPI가 과반이라는 것은 P5의 실수가 아니라, **P2 KR 체계가
  실행 단위를 담지 못했다**는 신호다. P5에서 KPI를 임의 신설해 메운 상태이므로
  P5만 고쳐도 근거가 없는 지표가 남는다.
○ 상충 상태: 이 판정을 P5 보완(Hold)으로 처리하면 KPI의 목표 연계 근거가
  영구 결손된다. 따라서 Hold가 아닌 Rollback이 맞다.

### 4. 재전파 범위 지정 [전체 재실행 회피]

| 재작업 대상 | 범위 | 재작업 불필요 |
|---|---|---|
| P2 | O2 하위 KR **2건 신설·1건 수정**만 — O1·O3 및 SO 체계 유지 | 미션·비전·SO1~SO4 |
| P3 | 수정 KR에 연계된 과제 **T4, T7** 2건의 목표 참조만 갱신 | 나머지 과제 11건 |
| P4 | T4·T7의 판정 근거 재확인 (등급 변동 없으면 원본 유지) | 총량 검증 결과 |
| P5 | `kpi_map` 3행 + `prerequisites_tracks` T7 1건 추가 | 로드맵·RACI·임계 경로 |

○ 전체 재실행 대비 **약 15% 범위**로 한정. 마일스톤·RACI·거버넌스는 불변.

### 5. rollback_log

```
RB-01 | 2026-09-22 | P5→P2 | 사유: [신규] KPI 과반(3/7), 목표 연계 근거 결손
      | 재전파: P2(KR 3건) → P3(T4,T7) → P4(판정 재확인) → P5(kpi_map 3행)
      | 불변 확정: 미션·비전·SO 체계·임계 경로·RACI
```

### 6. 차기 액션

○ `goal-setting-loop-p2`를 위 범위로 재실행 → `[DATA-P2-OUTPUT]` 재발급
○ 자동 관통 모드이므로 이후 Pass 구간은 보고 없이 진행

```markdown
# [ORCH-STATE]
- cycle: 1 / current: P2(재작업) / mode: 통합 / approval: auto-run
- approved: P1, P3(부분보류), P4(부분보류)
- rollback_log: RB-01
- assumptions_total: 9건 (P1 2 / P2 3 / P4 2 / P5 2)
- open_flags: legal_flags 1건 미해결(T9 — 법무 검토 병행 트랙)
```
