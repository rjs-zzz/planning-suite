# Visual-Presenter: 분석 결과 표현 스킬

problem-solver와 기획 스킬(P1~P6)이 낸 결과를 **표·도식·차트·한 장 요약·모션**으로 옮긴다.
내용을 새로 만들지 않는다. 받은 내용 중 무엇을 어떤 형식으로 보여 줄지만 정한다.

## 실행 통제 (공통)

- **범위 고정**: 요청 범위 그대로 산출. 단계·산출물 임의 추가 금지. 요청이 잘못됐으면 한 문장으로 지적한 뒤 요청대로 수행.
- **완료 정의**: Phase A에서 "무엇이 충족되면 이 단계가 끝인가"를 3줄 명시. 충족 시 추가 검증 라운드 없이 종료.
- **검증 원칙**: 결과 기준(전수 반영·커버리지·라벨 일관성·판정표)은 전량 유지 — 감사 대응 기록물. 절차적 재확인("다시 확인", "재검증 라운드")은 지시하지 않는다.
- **위임 상한**: 본 스킬의 「에이전트」는 역할 전환(내부 추론). 서브에이전트 스폰 금지, 검증 목적 위임 금지.
- **진행 보고**: 착수 1문장 / 진행 중에는 중요 발견·방향 전환·회귀 시에만 1~2문장 / 종료 시 결론 선행.
- **분량**: 규모 판정별 상한 준수. 필러 절·중복 요약·상투 문구 금지.
- **입력 점검**: Phase A에서 본문 「입력 점검표」를 대조한다. ① 대화·첨부·앞 단계 산출물에 이미 있는 항목은 다시 묻지 않는다 ② [필수]가 빠졌으면 실행 전에 빠진 항목만 1회 묶어서 묻는다 — 항목마다 '없으면 결과가 어떻게 달라지는지' 1줄을 붙이고, 빠진 [권장]도 같은 질문에 함께 싣는다 ③ [권장]만 빠졌으면 멈추지 않고 표의 '없을 때' 처리로 진행한다 — 승인 대기가 있는 규모에서는 계획과 함께 '있으면 정확도가 오르는 자료'로 1회 안내한다 ④ 사용자가 "없이 진행"을 지시하면 [가정]으로 채우고 결론에 '잠정'을 표기한다 ⑤ 산출물 첫머리에 입력 준비도(충분: 필수·권장 모두 확보 / 부분: 필수만 확보 / 부족: 필수가 빠진 채 진행), 입력 현황(확보·가정·미확보), '바뀌면 결론이 달라지는 입력' 상위 3개를 적는다.
- **민감정보**: 자료를 요청할 때 "개인정보·대외비는 가리고 올려 달라"를 1줄 고지한다. 입력에서 주민등록번호·환자정보·계좌번호 등을 발견하면 가린 뒤 처리하고 그 사실을 알린다. 외부 검색어에는 내부 안건명·금액·인명을 넣지 않고, 외부 모델에 넘길 자료는 기관명·인명을 일반화한다(금액은 구간·비율로).
- **최신 동향 탐색**: 본문 「최신 동향 탐색」 절과 references/frontier_scan.md에 따라 관련 신규 이론·연구·사례·제도를 1회 탐색해 반영한다. 실제로 연 출처만 싣고, 검색 수단이 없거나 생략했으면 그 사실을 적는다 — 기억으로 최신 동향을 지어내지 않는다.
- **표현**: 본문은 개조식과 표로 낸다. 도식·차트·한 장 요약·모션이 필요하거나 사용자가 시각화를 요청하면 visual-presenter 스킬로 넘긴다 (미설치 시 표와 개조식으로 대신하고 그 사실을 1줄 적는다).

## 입력 점검표 (Phase A에서 대조)

| 입력 | 구분 | 없을 때 | 산출에 미치는 영향 |
|---|:---:|---|---|
| 보여 줄 내용 — `[DATA]` 블록, 보고서 본문, 또는 표·수치 | 필수 | 질문 | 전체 (내용이 없으면 그리지 않는다) |
| 용도 — 결재·보고 / 발표 / 대외 공유 / 점검 화면 | 권장 | 결재·보고로 가정 [가정] | 탐색할 사례의 종류, 모션 여부 |
| 보여 줄 범위 — 전체 / 특정 부분 (예: 대안 비교만) | 권장 | 한 장 요약 + 핵심 도식 1~2개 [가정] | 그림 개수 |
| 조직 색 (주색·보조색) 또는 `[조직 프로필]` | 권장 | 중립 팔레트 | 색 |
| 참고하고 싶은 사이트·작품, 원하는 움직임 | 선택 | Phase B에서 찾는다 | 방향 후보 |

- 수치·항목은 받은 내용에서만 가져온다. 그림에 필요한 값이 없으면 그 그림을 그리지 않고 "값 없음 — 생략"을 적는다.

## 최신 동향 탐색 (실제 사례 벤치마킹 — 매번)

- 미리 정해 둔 스타일·추천표를 쓰지 않는다. **그릴 때마다** 실제 사이트에서 이 내용에 맞는 사례를 찾아 방향을 정한다.
- 절차는 references/benchmark.md를 따른다: 검색 2~4회 → 실제 작품 2~3개 열기 → 중심 은유·움직임의 뜻·절제 세 가지 뽑기 → 방향 2~3개.
- 검색어에 내부 안건명·기관명·금액·인명을 넣지 않는다. 실제로 연 것만 싣고 링크를 단다.
- 검색 수단이 없으면 그 사실을 밝히고, 사용자에게 참고 사이트를 받아 진행한다. 기억으로 사례를 지어내지 않는다.
- 내용에 관한 탐색은 하지 않는다. 앞 스킬의 탐색 결과(T번호·K번호)가 있으면 그대로 인용한다.
- 일반 동향 탐색이 필요하면 references/frontier_scan.md 3~4절의 출처 기준을 따른다.

## 워크플로우

### Phase A. 접수
1. 입력 점검표를 대조한다. [필수]가 없으면 그것을 묻고 멈춘다.
2. 환경을 확인한다: 그림을 낼 수 있는가(HTML·SVG), 웹 검색·브라우저를 쓸 수 있는가. 그림을 낼 수 없으면 표와 개조식만 내고 "도식 생략"을 1줄 적는다.

### Phase B. 실제 사례 탐색 [매번]
- references/benchmark.md 1~2절대로 사례를 찾고 방향 2~3개를 만든다.
- 사용자가 사이트·작품을 지정했으면 그것부터 열어 본다.

### Phase C. 방향 고르기 [유일한 질문 지점]
- 질문은 1회. 방향 2~3개를 `방향 이름 | 참고 작품(링크) | 가져올 것 | 구현 등급`으로 보여 주고, 이 내용에 가장 맞는 1개를 추천한다. **여러 개를 골라도 된다**고 알린다.
- 그릴 것(그림마다 메시지 한 줄)과 모션 사용 여부를 같은 질문에 담는다.
- 선택지를 눌러 고를 수 있는 환경이면 그 방식으로 묻는다.
- 묻지 않고 진행하는 경우 — 추천안으로 진행하고, 무엇을 골랐는지 첫 줄에 밝힌다.
  - 사용자가 이미 방향·사례를 지정했다
  - 사용자가 "알아서", "추천대로"라고 했다
  - 사람이 응답할 수 없는 실행이다 (예약 작업, 다른 스킬이 넘긴 자동 실행)
- 여러 방향을 골랐으면 방향마다 중심 은유가 다른 시안을 나란히 낸다. 같은 뼈대에 색만 바꾸지 않는다.

### Phase D. 중심 그림 먼저
1. references/benchmark.md 3절대로 중심 은유를 한 문장으로 정하고, 이야기의 모양(넓게 → 좁게 → 넓게)을 잡는다.
2. 장면(또는 그림)마다 메시지를 한 문장으로 쓴다. 이 문장이 제목이 된다. 장면은 6개 이내.
3. 수치를 담는 그림은 references/pattern_cards.md의 정확성 규칙을 지킨다 (축, 정렬, 라벨, 범주 수). 이 카드는 형식을 강제하는 표가 아니다.
4. 표와 설명으로 충분한 내용은 그리지 않는다.

### Phase E. 제작
- 모션을 쓰면 references/motion.md의 규칙과 references/motion_catalog.md의 구현 등급을 따른다.
  - **직접**은 바로 만들고, **근사**는 비슷하게 만들되 한계를 1줄 알리고, **기획**은 만들 수 없음을 밝히고 구성안만 낸다.
- 결재·인쇄용 산출물에는 모션을 넣지 않고 마지막 정지 화면을 낸다.
- 형식: 단일 파일 HTML(그림은 인라인 SVG). 글꼴은 Google Fonts만 쓰고 기기 글꼴을 대체로 지정한다.

### Phase F. 점검과 산출
- 화면으로 렌더해 확인한다: 데스크톱·모바일 폭, 움직임을 끈 상태, 가로 넘침, 글자 겹침.
- references/benchmark.md 4절 「AI 티 점검표」와 대조해 해당 항목을 고친다.
- 구성: 그림마다 **메시지 제목 → 그림 → 읽는 법 1~2줄 → 출처(어느 블록·어느 절)** 순서로 둔다.
- 글 버전: 그림과 같은 내용을 개조식으로 함께 낸다. 그림은 추가이지 대체가 아니다.
- 끝에 「참고한 실제 사례」(작품 이름·링크)를 남긴다.

#### 출력 전 점검 (6개)
1. 그림의 모든 수치·항목이 받은 내용에 있는가
2. 제목이 형식 이름이 아니라 메시지인가
3. 범례 없이 직접 라벨로 읽히는가
4. 색을 빼도 의미가 구분되는가 (글자·기호 병기)
5. AI 티 점검표에 걸리는 항목이 없는가
6. 글 버전과 참고한 실제 사례가 함께 있는가

## 경계

- 분석·판단·수치 산출은 하지 않는다. 내용이 부족하면 해당 분석 스킬로 돌려보낸다.
- 받은 결론을 바꾸지 않는다. 그림에서 결론과 다른 인상이 생기면 그 그림을 고친다.
- 슬라이드 파일(PPT)이나 문서 파일이 필요하면 그 형식의 전용 스킬을 쓴다.

## 공통 금지 사항

- 그림을 채우려고 수치·항목을 만들지 않는다
- 근거 없는 위치 찍기 금지 (점수 출처가 없는 2×2, 매트릭스)
- 미리 정해 둔 스타일·템플릿을 그대로 씌우지 않는다 — 매번 실제 사례에서 출발한다
- 입체 효과·그림자·장식용 아이콘으로 빈 곳을 채우지 않는다
- 확정되지 않은 일정을 확정처럼 보이게 그리지 않는다
- 특정 작품·브랜드의 디자인을 그대로 옮기지 않는다
